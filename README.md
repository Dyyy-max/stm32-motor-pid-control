# STM32F103 直流电机 PWM 调速 + PID 闭环稳速 + 脉冲测量（含完整硬件测试方案）

## 项目简介

本人是电子信息工程专业在校生，本项目是独立完成的嵌入式控制与**信号测量**综合实践，目标岗位为**仪器仪表 / 智能电能表行业硬件测试工程师**，全程以测试工程师视角进行需求分解、用例设计、缺陷闭环与测试验证：

- 基于 STM32F103C8T6（HAL 库）实现按键启停、LED 状态指示、PWM 调速、增量式 PID 转速闭环；
- 使用 **TIM3 输入捕获实现脉冲频率测量与脉冲个数累计**（PA6），可用一根跳线与 PWM 输出（PA1）短接做**信号回环自测**——该方法与电能表校表脉冲误差测试（imp/kWh）原理相同；
- 采用「**软件仿真验证 → 代码静态走查 → 硬件台架实测**」的分层测试策略；
- 通过串口周期性输出运行数据，用于观测、记录与分析；
- 静态走查中发现并记录了 2 个高严重度缺陷（D-001 引脚复用冲突、D-002 SWD 调试口被关闭），**代码均已完成修复**，D-001 待上板回归测试。

通过本项目重点实践了**需求分解、测试用例编制、测试执行、信号测量、缺陷定位到闭环、测试文档编写**等硬件测试岗位核心技能。

### 外设关键参数

- **PWM**：TIM2_CH2（PA1），预分频 PSC=71 → 计数时钟 72MHz/(71+1)=1MHz；自动重装载 ARR=999 → PWM 频率 1kHz；占空比分辨率 1/1000 = **0.1%**，输出范围 0~999；
- **输入捕获**：TIM3_CH1（PA6），计数时钟同为 1MHz（**1 个计数 = 1µs**），ARR=65535 自由计数，上升沿触发捕获中断；相邻两次捕获值之差 = 信号周期（µs），频率 = 1,000,000 / 周期；同时累计脉冲个数；超过 300ms 无脉冲判定为无信号；
- **串口**：USART1，9600 / 8 数据位 / 1 停止位 / 无校验（8N1），无流控；
- **控制周期**：100ms（10Hz 控制环路）；
- 硬件版电机转速反馈当前由软件模型模拟，**实际上板需接入电机驱动芯片（如 TB6612）与编码器反馈**。

## 控制原理

采用增量式 PID，输出直接作为 PWM 比较值：

```
Δu(k) = Kp·[e(k)−e(k−1)] + Ki·e(k) + Kd·[e(k)−2e(k−1)+e(k−2)]
u(k)  = u(k−1) + Δu(k)
```

相对位置式 PID：无需累积积分项、计算量小；输出为增量，异常切换时冲击小；并带 0~999 输出限幅。

## 脉冲测量原理（与电能表校表同源）

输入捕获测频/计数的工作过程：

```
PA6输入信号 ──↑________↑________↑________  （上升沿）
TIM3计数器  ──  1000     2000     3000    （每1µs加1）
                └─ 锁存 ─┘└─ 锁存 ─┘
捕获中断：周期 = 2000-1000 = 1000µs → f = 1000Hz；脉冲计数 +1
```

- **测周期法（本项目）**：相邻上升沿的定时器锁存值之差即周期，适合中低频信号；
- **闸门计数法**：固定时间 T 内统计脉冲个数 N，f = N/T，适合高频信号（代码中的 `ic_pulse_count` 即脉冲累计，配合 100ms 控制周期可直接做闸门统计）。

**与智能电能表测试的对应关系**：电能表面板校表灯每输出一个脉冲代表固定电能（脉冲常数，如 1600 imp/kWh）。误差测试时，标准功率源给出已知功率 P，校验仪在固定时间内**统计被校表脉冲个数 N**，与理论脉冲数 N₀ 比较：误差 γ =（N−N₀）/N₀ ×100%。这与本项目"单位时间数 PA6 脉冲个数"的软件流程完全一致，区别仅在于现场用的是光电采样器夹表脉冲灯、标准源提供基准。此外 RS485/红外通信测试中也常用类似手段统计通信脉冲、核对波特率与时序。

**回环自测方法（无需外接信号源）**：用 1 根杜邦线把 PA1（PWM 输出）与 PA6（捕获输入）短接，按键启动电机后，PA6 即可捕获到 1kHz PWM 波——输出信号由自己产生、再由自己测量闭环验证，是硬件测试中常用的"信号环回（loopback）"思路（类似串口 TX/RX 短接自测）。

### 4. 闭环性能评价指标

参照控制系统常规评价方法，用串口记录阶跃响应数据，关注：

- **上升时间**：转速从 10% 上升到 90% 目标值所需时间；
- **超调量 σ%**：最大峰值超出目标值的百分比；
- **调节时间**：进入目标值 ±5% 误差带并保持的时间；
- **稳态误差**：收敛后实测值与目标值的残差；
- **振荡次数**：调节时间内穿越目标值的次数。

整定方法：先增大 Kp 至出现轻微振荡，再加入 Ki 消除稳态误差，最后用 Kd 抑制超调；对比多组 (Kp, Ki, Kd) 的响应曲线后定型（硬件版 Kp=2.0 / Ki=0.1 / Kd=0.05）。

### 5. 边界与异常测试点

- 输出边界：PWM 比较值 0 与 999 限幅验证；
- 反馈边界：模拟反馈速度钳位 0~1500，验证异常反馈不导致输出失控；
- 随机扰动：在反馈中注入 ±50 随机波动，验证闭环抑制能力；
- 频繁启停 / 启动瞬间大偏差：验证积分饱和与限幅保护；
- 串口断线：通信中断不影响控制环路（打印为非阻塞观测手段）。

### 6. 静态测试缺陷记录

**D-001｜PA0 按键与 TIM2_CH1 PWM 引脚复用冲突，PWM 无物理输出｜严重度：高（上板功能阻断）｜状态：✅ 代码已修复，待上板回归**

- **现象**：硬件版上板后示波器在 PA0 测不到 PWM 波形；
- **根因**：
  1. CubeMX 生成的 `HAL_TIM_MspPostInit()` 将 PA0 配置为 TIM2_CH1 复用推挽输出，而手写的 `MX_GPIO_Init()` 又将 PA0 配置为按键上拉输入，同一引脚两个功能冲突；
  2. 手写的 `MX_TIM2_Init()` 未调用 `HAL_TIM_MspPostInit()`，定时器通道虽已使能，但 GPIO 未切换到复用功能，PWM 无法输出到引脚；
  3. `main.c` 文件头注释「PA1: TIM2_CH1」有误，TIM2_CH1 默认引脚为 PA0，PA1 对应 TIM2_CH2；
- **修复方案（采用方案①：PWM 改走 TIM2_CH2/PA1，PA0 保留给按键）**，实际改动：
  1. `User/main.c`：PWM 配置/启动/比较值全部由 `TIM_CHANNEL_1` 改为 `TIM_CHANNEL_2`（3 处 `__HAL_TIM_SET_COMPARE` 同步）；`MX_TIM2_Init()` 中补调 `HAL_TIM_MspPostInit()`；修正文件头与函数注释；
  2. `Core/Src/stm32f1xx_hal_msp.c`：`HAL_TIM_MspPostInit()` 改为把 **PA1** 配置为 TIM2_CH2 复用推挽，不再动 PA0；
  3. `Motor_PWM_Project.ioc`：PA0 改为上拉输入（KEY1），PA1 改为 `TIM2_CH2` PWM 通道，并补齐 PSC=71、ARR=999，保证重新生成代码时配置一致；
- **修复后引脚占用核对**：PA0=KEY1（输入）、PA1=PWM（复用输出）、PA9/PA10=USART1、PB0=方向、PC13=LED，无重叠；
- **回归测试（待执行）**：上板后按 TC-02、TC-04、TC-05、TC-06 复测——PA1 应测到 1kHz PWM 且占空比随 PID 变化，PA0 按键启停与消抖功能正常。

**D-002｜CubeMX 误选 No Debug，SWD 下载口被固件关闭，存在"烧录一次后失联"风险｜严重度：高（阻断开发与产线烧录）｜状态：✅ 代码已修复**

- **现象**：若先烧录该固件，ST-Link 再次连接时报 "No ST-LINK detected / target ID not matched"，无法下载与调试；
- **根因**：`.ioc` 中 SYS→Debug 被设为 No Debug，`HAL_MspInit()` 执行 `__HAL_AFIO_REMAP_SWJ_DISABLE()`，同时关闭了 JTAG-DP 与 SW-DP——而 STM32F103 的 SWD 引脚（PA13/SWDIO、PA14/SWCLK）上电默认是调试功能，被固件主动禁用后下载器便无法接管；
- **修复方案**：改为 Serial Wire 模式（仅禁 JTAG、保留 SWD）：
  1. `Core/Src/stm32f1xx_hal_msp.c`：宏改为 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`；
  2. `.ioc`：`VP_SYS_VS_ND/No_Debug` 改为 `VP_SYS_VS_SWO/Serial Wire`，保证重新生成一致；
- **经验教训**：新建 CubeMX 工程第一步就应确认 SYS→Debug=Serial Wire；调试口属于"不可被应用固件关闭的基础设施"，配置走查应将其列为必检项；
- **救砖方法（若已烧录旧固件失联）**：Keil/ST-Link Utility 中按住板子复位键不松 → 点击 Connect（Under Reset 模式）→ 释放复位 → 连接成功后立即擦除整片 Flash，再烧录修复后的固件。

## 调试中遇到的问题与解决

### 1. 转速震荡、启动超调大

PID 参数不合理导致波动大、启动冲值过高。通过仿真版快速对比多组参数，加入输出限幅，最终响应平稳（方法见「闭环性能评价指标」）。

### 2. 硬件依赖高、调试效率低

增加纯软件仿真版本，用一阶响应模型模拟电机，先在仿真中验证算法与整定参数，再向硬件移植，调试周期显著缩短——与工业界「先仿真验证、后台架实测」的测试流程一致。

### 3. 代码结构杂乱

将 PID 算法独立为 `pid.c/pid.h` 模块，主程序只保留业务逻辑，统一注释规范，便于逐模块编写测试用例。

## 编译 & 运行

### 仿真版（推荐先跑）

1. Keil MDK5 打开 `PID_Sim/PID_simulation.uvprojx`（目标芯片 STM32F103C8）；
2. 选择软件仿真模式运行，打开串口仿真窗口；
3. 观察「周期 / 目标值 / 实际转速 / PID 输出」数据，修改 PID 参数对比响应。

### 硬件版

1. 用 STM32CubeMX 打开 `.ioc`，确认时钟与引脚配置（PA0=按键、PA1=TIM2_CH2 PWM、PA6=TIM3_CH1 输入捕获、SYS Debug=Serial Wire）；
2. Keil 打开工程编译（Rebuild），用 **ST-Link 经 SWD 接口下载**：接线 SWDIO→PA13、SWCLK→PA14、GND→GND、3.3V→3.3V（共 4 根，D-002 已确保该接口不被固件关闭）；
3. 串口助手设为 9600, 8N1；用 1 根杜邦线短接 **PA1 与 PA6**（回环自测，对应 TC-12~TC-14）；
4. 按 KEY1 启动，串口应打印 `CAP Freq:1000 Hz` 且 `Pulses` 每 100ms 增加约 100；拔掉跳线后频率显示 0；
5. 进阶验证：示波器探头接 PA1 测波形（TC-05/06），逻辑分析仪接 PA9 抓串口帧（TC-07）。
