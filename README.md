# STM32F103 直流电机 PWM 调速 + PID 闭环稳速 + 脉冲测量（含完整硬件测试方案）

## 项目简介

本人是电子信息工程专业在校生，本项目是独立完成的嵌入式控制与**信号测量**综合实践，全程以测试工程师视角进行需求分解、用例设计、缺陷闭环与测试验证：

- 基于 STM32F103C8T6（HAL 库）实现按键启停、LED 状态指示、PWM 调速、增量式 PID 转速闭环；
- 使用 **TIM3 输入捕获实现脉冲频率测量与脉冲个数累计**（PA6），可用一根跳线与 PWM 输出（PA1）短接做**信号回环自测**——输出信号由自己产生、再由自己测量闭环验证；
- **江协科技 PID 入门套件实物版**（`User/main_kit.c`，与回环版同一工程、编译时二选一）：驱动 TB6612FNG（双脚方向真值表 + 刹车）、霍尔正交编码器接入 **TIM3 编码器接口模式硬件四倍频**（408 计数/输出轴一圈，M 法测速），增量式 PID 运行在**真实转速反馈**上，软件模拟反馈仅保留在无硬件的回环版中；
- 基于**江协科技 PID 入门套件**的硬件设计参数（TB6612FNG datasheet、25GA370 编码电机手册、控制板原理图）完成引脚级适配与设计参数计算，采用「**硬件设计 → 固件开发 → 静态走查 → 台架验证**」的工程测试流程；
- 通过串口周期性输出运行数据，用于观测、记录与分析；
- 静态走查中发现并记录了 3 个缺陷（D-001 引脚复用冲突、D-002 SWD 调试口被关闭，严重度高；D-003 HAL 编码器 MSP 钩子误用导致 PA7 漏初始化，严重度中），**代码均已完成修复**，D-001 待上板回归测试。

通过本项目重点实践了**需求分解、测试用例编制、测试执行、信号测量、缺陷定位到闭环、测试文档编写**等测试工程核心技能。

### 外设关键参数

- **PWM（回环版）**：TIM2_CH2（PA1）；**PWM（套件实物版）**：TIM2_CH1（PA0=PWMA）。两者均为 PSC=71 → 计数时钟 72MHz/(71+1)=1MHz；ARR=999 → PWM 频率 1kHz；占空比分辨率 1/1000 = **0.1%**，输出范围 0~999；
- **输入捕获（回环版）**：TIM3_CH1（PA6），计数时钟同为 1MHz（**1 个计数 = 1µs**），ARR=65535 自由计数，上升沿触发捕获中断；相邻两次捕获值之差 = 信号周期（µs），频率 = 1,000,000 / 周期；同时累计脉冲个数；超过 300ms 无脉冲判定为无信号；
- **编码器接口（套件实物版）**：TIM3 工作在 `ENCODERMODE_TI12`，PA6/PA7 两相所有边沿均硬件计数（**四倍频**），输入滤波 N=8；ARR=65535，CNT 带符号、反转递减；M 法测速闸门 100ms，RPM = ΔCNT × 60 ÷ 408 ÷ 0.1（408 = 11PPR × 减速比 9.2767 × 4 倍频）；620RPM 满速时 ΔCNT ≈ 422/100ms；
- **串口**：USART1，9600 / 8 数据位 / 1 停止位 / 无校验（8N1），无流控；
- **控制周期**：100ms（10Hz 控制环路，与测速闸门等长）；
- **转速反馈说明**：回环版（`main.c`）在无驱动/电机时用软件模型模拟反馈以验证流程；套件实物版（`main_kit.c`）使用霍尔编码器真实测速闭环，模拟代码已不参与实物版编译。

## 控制原理

采用增量式 PID，输出直接作为 PWM 比较值：

```
Δu(k) = Kp·[e(k)−e(k−1)] + Ki·e(k) + Kd·[e(k)−2e(k−1)+e(k−2)]
u(k)  = u(k−1) + Δu(k)
```

相对位置式 PID：无需累积积分项、计算量小；输出为增量，异常切换时冲击小；并带 0~999 输出限幅。

## 脉冲测量原理

输入捕获测频/计数的工作过程：

```
PA6输入信号 ──↑________↑________↑________  （上升沿）
TIM3计数器  ──  1000     2000     3000    （每1µs加1）
                └─ 锁存 ─┘└─ 锁存 ─┘
捕获中断：周期 = 2000-1000 = 1000µs → f = 1000Hz；脉冲计数 +1
```

- **测周期法（本项目）**：相邻上升沿的定时器锁存值之差即周期，适合中低频信号；
- **闸门计数法**：固定时间 T 内统计脉冲个数 N，f = N/T，适合高频信号（代码中的 `ic_pulse_count` 即脉冲累计，配合 100ms 控制周期可直接做闸门统计）。

**回环自测方法（无需外接信号源）**：用 1 根杜邦线把 PA1（PWM 输出）与 PA6（捕获输入）短接，按键启动电机后，PA6 即可捕获到 1kHz PWM 波——输出信号由自己产生、再由自己测量闭环验证，是硬件测试中常用的"信号环回（loopback）"思路（类似串口 TX/RX 短接自测）。

## 江协 PID 入门套件实物版（真实 TB6612 + 霍尔编码器闭环）

`User/main_kit.c` 是面向**江协科技 PID 入门套件**（控制板 V1.0 + 25GA370 霍尔编码电机）的实物固件，与回环版共用同一个 Keil 工程、同一份 `pid.c`，仅主程序文件在编译时二选一（切换步骤见「编译 & 运行」）。

**硬件链路**：

```
STM32 PA0/PWM(TIM2_CH1,1kHz) ──► TB6612 PWMA ──► 电机 A 路绕组
STM32 PB12/PB13(AIN1/AIN2)   ──► TB6612 方向真值表（STBY 板载常使能）
电机霍尔 AB 相 ──► PA6/PA7 ──► TIM3 编码器接口(硬件四倍频) ──► 100ms M 法测速 ──► 增量式PID ──► PWM
```

**TB6612FNG 方向真值表**（软件里停止统一用 11=短接刹车）：

| AIN1(PB12) | AIN2(PB13) | 电机状态 |
|---|---|---|
| 1 | 0 | 正转（PWM 调速） |
| 0 | 1 | 反转（本固件未使用） |
| 1 | 1 | 刹车（两端短接制动） |
| 0 | 0 | 滑行（高阻自由停转） |

**编码器线数核算**（资料参数与代码常量互相印证）：霍尔 11 个脉冲/电机轴每圈 × 减速比 9.2767 ≈ 102 脉冲/输出轴每圈/相 × 四倍频 = **408 计数/输出轴每圈**，与用户手册"电机轴一圈 AB 相共 408 个边沿"一致。这一数值是 TC-15 手转校验的判据，也是转速换算的基准。

**基于硬件设计参数的预期串口输出**（9600 8N1，100ms 一帧；转速值依据：电机一阶响应模型 τ≈0.1s + 编码器 408CPR + PID Kp1.2/Ki0.3；**上台架后以实测数据替代**）：

```
Motor Stopped (TB6612 brake)                       <- 上电先进入安全刹车态
=== STM32 PID Kit Firmware (TB6612 + 408CPR Encoder) ===
System Initialized! K1(PB10)=start/stop, sample=100ms
[STOP] Spd:     0 RPM | CNT:    0 | brake
[STOP] Spd:    58 RPM | CNT:    4 | brake        <- 手转轴：CNT随手势变化，整圈累计约408
Motor Started (TB6612 FWD, target 150 RPM)
[RUN ] Tgt: 150 RPM | Spd:    88 RPM | CNT:   60 | PWM:225/999
[RUN ] Tgt: 150 RPM | Spd:   146 RPM | CNT:   99 | PWM:246/999
[RUN ] Tgt: 150 RPM | Spd:   151 RPM | CNT:  103 | PWM:241/999   <- 稳态：误差约 ±2RPM
[RUN ] Tgt: 150 RPM | Spd:   118 RPM | CNT:   80 | PWM:279/999   <- 手捏轴加负载：PWM自动顶上去
[RUN ] Tgt: 150 RPM | Spd:   149 RPM | CNT:  101 | PWM:243/999   <- 撤负载后回归
Motor Stopped (TB6612 brake)
```

**PID 参数**：实物版以 RPM 为工程单位，初值 Kp=1.2 / Ki=0.3 / Kd=0（保守起步值，代码宏 `PID_KP/KI/KD`，**上板必须重新整定**）：先 Kp 至轻微振荡 → 加 Ki 消静差 → 必要时小 Kd 抑超调；目标转速宏 `TARGET_RPM_DEFAULT=150`，验证通过后再向 300、620RPM 提升。

**安全设计**：① 上电时 AIN1/AIN2 先写 11 刹车电平再切换为输出，杜绝引脚初始化瞬间毛刺；② PWM 比较值初值 0；③ 未验证编码器极性前不接动力电；④ 停止即短接刹车而非滑行。

| TC-13 | 脉冲计数 | 同上，每 100ms 读取一次 `Pulses` 计数差值 | 100ms 内脉冲增量 ≈ 100 个（1000×0.1），计数单调递增不丢脉冲 | 计数差 100±1；停止后计数冻结 |
| TC-14 | 无信号判定 | 拔掉 PA1-PA6 跳线 | 300ms 后 `CAP Freq` 显示 0，系统其他功能不受影响 | 频率归零、不出现乱值 |
| TC-15 | 编码器线数/极性（套件版） | 仅 USB 供逻辑电、VIN 悬空（VM 无电），插好 6P 插头后手转输出轴整整一圈 | 各 100ms 帧 CNT 增量之和 ≈ 408；反转时 CNT 为负；停止后 CNT 归零冻结 | 累计 408 ± 2；方向符号正确 |
| TC-16 | 真实转速闭环（套件版） | 接 VIN 5~12V（首次建议 5V），K1 启动，目标 150RPM | 转速收敛并稳定在目标附近，串口 `Spd` 与非接触转速计/示波器反算一致 | 稳态误差 ≤±5%，无持续振荡 |
| TC-17 | 负载调整率（套件版） | 稳态运行中用手轻捏轴施加/撤除负载 | PWM 自动增大/回落，转速短时偏离后恢复目标，不堵转、不发散 | 跌速 ≤20%，2s 内恢复 |
| TC-18 | 刹车与上电安全（套件版） | 运行中按 K1 停止；重新上电瞬间观察 | 立即短接刹车快速停转；上电/复位瞬间电机不发生冲转或抖动 | 停转时间可测；上电零冲转 |

### 4. 闭环性能评价指标

参照控制系统常规评价方法，用串口记录阶跃响应数据，关注：

- **上升时间**：转速从 10% 上升到 90% 目标值所需时间；
- **超调量 σ%**：最大峰值超出目标值的百分比；
- **调节时间**：进入目标值 ±5% 误差带并保持的时间；
- **稳态误差**：收敛后实测值与目标值的残差；
- **振荡次数**：调节时间内穿越目标值的次数。

整定方法：先增大 Kp 至出现轻微振荡，再加入 Ki 消除稳态误差，最后用 Kd 抑制超调；对比多组 (Kp, Ki, Kd) 的响应曲线后定型（回环版软件反馈目标量纲下 Kp=2.0 / Ki=0.1 / Kd=0.05；套件实物版以 RPM 为单位，初值 Kp=1.2 / Ki=0.3 / Kd=0，待上板整定）。实物台架另测**负载调整率**：施加额定扰动后转速最大跌落与恢复时间（TC-17）。

### 5. 边界与异常测试点

- 输出边界：PWM 比较值 0 与 999 限幅验证；
- 反馈边界：模拟反馈速度钳位 0~1500，验证异常反馈不导致输出失控；
- 随机扰动：在反馈中注入 ±50 随机波动，验证闭环抑制能力；
- 频繁启停 / 启动瞬间大偏差：验证积分饱和与限幅保护；
- 串口断线：通信中断不影响控制环路（打印为非阻塞观测手段）；
- 套件版新增：编码器掉线/单相接触不良（CNT 异常归零或只剩半频）、上电瞬间方向脚毛刺（TC-18）、堵转时 PWM 顶满限幅的持续时长与发热风险。

### 6. 静态测试缺陷记录

**D-001｜PA0 按键与 TIM2_CH1 PWM 引脚复用冲突，PWM 无物理输出｜严重度：高（上板功能阻断）｜状态：✅ 代码已修复，待上板回归**

- **现象**：硬件版上板后示波器在 PA0 测不到 PWM 波形；
- **根因**：
  1. CubeMX 生成的 `HAL_TIM_MspPostInit()` 将 PA0 配置为 TIM2_CH1 复用推挽输出，而手写的 `MX_GPIO_Init()` 又将 PA0 配置为按键上拉输入，同一引脚两个功能冲突；
  2. 手写的 `MX_TIM2_Init()` 未调用 `HAL_TIM_MspPostInit()`，定时器通道虽已使能，但 GPIO 未切换到复用功能，PWM 无法输出到引脚；
  3. `main.c` 文件头注释「PA1: TIM2_CH1」有误，TIM2_CH1 默认引脚为 PA0，PA1 对应 TIM2_CH2；
- **修复方案（采用方案①：PWM 改走 TIM2_CH2/PA1，PA0 保留给按键）**，实际改动：
  1. `User/main.c`：PWM 配置/启动/比较值全部由 `TIM_CHANNEL_1` 改为 `TIM_CHANNEL_2`（3 处 `__HAL_TIM_SET_COMPARE` 同步）；`MX_TIM2_Init()` 中补调 `HAL_TIM_MspPostInit()`；修正文件头与函数注释；
  2. `Core/Src/stm32f1xx_hal_msp.c`：`HAL_TIM_MspPostInit()` 改为把 **PA1** 配置为 TIM2_CH2 复用推挽，不再动 PA0；
  3. `Motor_PWM_Project.ioc`：PA0 改为上拉输入（KEY1），PA1 改为 `TIM2_CH2` PWM 通道，并补齐 PSC=71、ARR=999，保证重新生成代码时配置一致；
- **修复后引脚占用核对**：PA0=KEY1（输入）、PA1=PWM（复用输出）、PA9/PA10=USART1、PB0=方向、PC13=LED，无重叠；
- **回归测试（待执行）**：上板后按 TC-02、TC-04、TC-05、TC-06 复测——PA1 应测到 1kHz PWM 且占空比随 PID 变化，PA0 按键启停与消抖功能正常。

**D-002｜CubeMX 误选 No Debug，SWD 下载口被固件关闭，存在"烧录一次后失联"风险｜严重度：高（阻断开发与产线烧录）｜状态：✅ 代码已修复**

- **现象**：若先烧录该固件，ST-Link 再次连接时报 "No ST-LINK detected / target ID not matched"，无法下载与调试；
- **根因**：`.ioc` 中 SYS→Debug 被设为 No Debug，`HAL_MspInit()` 执行 `__HAL_AFIO_REMAP_SWJ_DISABLE()`，同时关闭了 JTAG-DP 与 SW-DP——而 STM32F103 的 SWD 引脚（PA13/SWDIO、PA14/SWCLK）上电默认是调试功能，被固件主动禁用后下载器便无法接管；
- **修复方案**：改为 Serial Wire 模式（仅禁 JTAG、保留 SWD）：
  1. `Core/Src/stm32f1xx_hal_msp.c`：宏改为 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`；
  2. `.ioc`：`VP_SYS_VS_ND/No_Debug` 改为 `VP_SYS_VS_SWO/Serial Wire`，保证重新生成一致；
- **经验教训**：新建 CubeMX 工程第一步就应确认 SYS→Debug=Serial Wire；调试口属于"不可被应用固件关闭的基础设施"，配置走查应将其列为必检项；
- **救砖方法（若已烧录旧固件失联）**：Keil/ST-Link Utility 中按住板子复位键不松 → 点击 Connect（Under Reset 模式）→ 释放复位 → 连接成功后立即擦除整片 Flash，再烧录修复后的固件。

**D-003｜HAL 编码器 MSP 回调钩子误用：自定义 `HAL_TIM_Encoder_MspInit` 永不执行，PA7 漏初始化｜严重度：中（功能侥幸可用但不可靠）｜状态：✅ 代码已修复**

- **现象**：套件版代码中写了 `HAL_TIM_Encoder_MspInit()` 期望配置 TIM3 时钟与 PA6/PA7，但该函数在 STM32F1 HAL 中**根本不会被调用**；编码器之所以"看似能工作"，是因为 PA6/PA7 复位后恰为浮空输入、且共享 MSP 分支顺手配了 PA6——B 相（PA7）实际处于未显式配置状态；
- **根因（HAL 调用链静态走查）**：`HAL_TIM_Encoder_Init()`（HAL 源码）内部仅调用 `TIM_Base_SetConfig()` 并执行 `HAL_TIM_Base_Init(htim)`，后者回调的是 **`HAL_TIM_Base_MspInit()`**——编码器模式**没有**独立的 `Encoder_MspInit` 钩子（CubeMX 生成的编码器 MSP 代码也是放在 `HAL_TIM_Base_MspInit` 的对应 Instance 分支里）。工程 `Core/Src/stm32f1xx_hal_msp.c` 的 TIM3 分支是回环版输入捕获的配置：只配 PA6 + 使能 TIM3 NVIC，既不配 PA7，套件版也不需要该中断；
- **修复方案**（不改动两版共享的 msp.c，避免影响回环版 NVIC/PA6 配置）：在 `User/main_kit.c` 的 `MX_TIM3_Encoder_Init()` 中，调用 `HAL_TIM_Encoder_Init()` **之前**显式完成：① `__HAL_RCC_TIM3_CLK_ENABLE()`；② `__HAL_RCC_GPIOA_CLK_ENABLE()`；③ PA6/PA7 配为 `GPIO_MODE_AF_INPUT + GPIO_NOPULL`；并删除永不执行的自定义 `HAL_TIM_Encoder_MspInit` 死代码。④ **关键顺序**：`HAL_NVIC_DisableIRQ(TIM3_IRQn)` 必须放在 `HAL_TIM_Encoder_Init()` **之后**——Init 内部经 Base_Init 回调共享 MSP 时会执行 `EnableIRQ(TIM3_IRQn)`，关中断放在 Init 之前会被立刻覆盖（编码器模式不开 DIER 中断位，实际不进 ISR，但 NVIC 必须显式关死，与 it.c 中仍存在的 TIM3_IRQHandler 解耦）；
- **台架验证点**：TC-15 手转整圈 408±2 计数——若 PA7 悬空导致 B 相漏边沿，四倍频会退化为二倍频/丢脉冲，该用例正是此缺陷的回归判据；
- **经验教训**："写了弱符号覆盖函数"≠"HAL 会调用它"，外设初始化类缺陷必须沿 HAL 源码实际调用链走查；同一 Instance 被两种外设模式（输入捕获/编码器）复用时，共享 MSP 分支是隐性耦合点，模式切换后必须重新核对 MSP 配置集是否完整；凡是要撤销 MSP 副作用的动作（如本例关闭 NVIC），执行顺序必须排在 `HAL_xxx_Init()` 之后，否则会被 Init 内部的 MSP 调用覆盖。

## 调试中遇到的问题与解决

### 1. 转速震荡、启动超调大

PID 参数不合理导致波动大、启动冲值过高。通过 `PID_Sim/` 离线验证快速对比多组参数，加入输出限幅，最终响应平稳（方法见「闭环性能评价指标」）。

### 2. 硬件设计参数确定与固件适配

基于江协套件原理图和元件 datasheet 完成引脚级适配（PWM 通道、TB6612 双脚方向、编码器接口模式），通过时钟树计算确定 PWM 频率与测速闸门，通过编码器手册核算 408CPR 确定转速换算系数——所有设计参数均可溯源到硬件文档，上台架前即完成固件与测试用例编写。

### 3. 代码结构杂乱

将 PID 算法独立为 `pid.c/pid.h` 模块，主程序只保留业务逻辑，统一注释规范，便于逐模块编写测试用例。

## 编译 & 运行

### PID 算法离线验证（PID_Sim，辅助工具）

1. Keil MDK5 打开 `PID_Sim/PID_simulation.uvprojx`（目标芯片 STM32F103C8）；
2. 选择软件仿真模式运行，打开串口仿真窗口；
3. 观察「周期 / 目标值 / 实际转速 / PID 输出」数据，修改 PID 参数对比响应。此工具仅用于算法收敛性离线验证，不替代硬件台架测试。

### 硬件版（回环自测版，main.c，工程默认）

1. 用 STM32CubeMX 打开 `.ioc`，确认时钟与引脚配置（PA0=按键、PA1=TIM2_CH2 PWM、PA6=TIM3_CH1 输入捕获、SYS Debug=Serial Wire）；
2. Keil 打开工程编译（Rebuild），用 **ST-Link 经 SWD 接口下载**：接线 SWDIO→PA13、SWCLK→PA14、GND→GND、3.3V→3.3V（共 4 根，D-002 已确保该接口不被固件关闭）；
3. 串口助手设为 9600, 8N1；用 1 根杜邦线短接 **PA1 与 PA6**（回环自测，对应 TC-12~TC-14）；
4. 按 KEY1 启动，串口应打印 `CAP Freq:1000 Hz` 且 `Pulses` 每 100ms 增加约 100；拔掉跳线后频率显示 0；
5. 进阶验证：示波器探头接 PA1 测波形（TC-05/06），逻辑分析仪接 PA9 抓串口帧（TC-07）。

### 套件实物版（main_kit.c，江协 PID 入门套件）

**Keil 中把主程序从 main.c 切换为 main_kit.c（两者都含 main 函数，不能同时参与编译）**：

1. 左侧 Project 树右键 `main.c` → *Options for File 'main.c'…* → 勾选 **Exclude from Build**（从编译中排除）→ OK；
2. 右键 `User` 分组 → *Add Existing Files to Group 'User'…* → 文件类型选 *All files* → 选中 `User/main_kit.c` 添加 → Close；
3. **Rebuild**（不是 Build）确认 0 Error；随后正常 ST-Link 下载。切回回环版时反向操作：对 `main_kit.c` 勾选 Exclude、取消 `main.c` 的勾选即可。

**分阶段安全上电（对应 TC-15~18，务必按顺序）**：

> 关键事实：编码电机是 **PH2.0-6P 一体插头**（针序 M+/GND/EB/EA/3V3/M-），电机绕组与编码器在同一个插头上，无法"只插编码器不接电机"。安全隔离的正确做法是**让 TB6612 的 VM 动力电与 3.3V 逻辑电分开供给**：VM 来自底板 VIN（DC 座/端子，5~12V），3.3V 来自最小系统板 USB 口经板载 LDO。

1. **只供逻辑电（VM 无电，电机物理上不可能转）**：USB 线接最小系统板 USB 口（手册正常使用时不用此口，此处作调试供电）→ 板载 LDO 产出 3.3V 供给 STM32/编码器/TB6612 逻辑侧；底板 VIN（DC 座/接线端子）**悬空不接**；连好 SWD 四线，编译下载后复位，串口应打印 `System Initialized!`；
2. **编码器单项验证（TC-15）**：插好电机 6P 插头（此时 VM 无电，TB6612 不驱动），用手慢转输出轴一整圈：各帧 `CNT` 增量之和应 ≈ 408，反向为负；若正转显示负值，对调插头上 EA/EB 两相，或在代码中把 `ENC_CH1_POLARITY` 改为 `FALLING`；
3. **PWM 空载验证**：示波器探头接控制板 PWMA 网络（PA0），按 K1 后应看到 1kHz、占空比随 PID 变化的波形（VM 无电，电机不转）；
4. **最后接动力电**：6P 插头已在步骤 2 插好，只需给底板 VIN 接 **5~12V（首次建议先 5V，即使固件异常转速也更低）**；按 K1 启动，电机会从 0 爬升到 150RPM 并稳住；观察 `Spd` 稳态误差（TC-16），手捏输出轴做负载测试（TC-17），再按 K1 验证刹车（TC-18，刹车态下停止后手转会感到明显阻尼，为正常现象）；
5. 异常处置：若接动力电后电机满速冲转或异响，立即断开 VIN 电源——优先排查 AIN1/AIN2 接线与编码器极性。
